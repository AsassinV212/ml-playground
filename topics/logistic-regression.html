From a line to a probability

A linear model computes a score z = w₁x₁ + w₂x₂ + b. The boundary z = 0 is a straight line; z is positive on one side and negative on the other, and its size grows with the distance from the line. To turn the score into a probability we squash it with the sigmoid:

p(blue) = σ(z) = 1 / (1 + e^(−z))

Far on the blue side p → 1, far on the coral side p → 0, and exactly on the line p = 0.5.

A physics picture: the Fermi–Dirac distribution

The sigmoid is the Fermi–Dirac function 1 / (1 + e^((E − μ)/kT)) from statistical physics. The distance from the boundary plays the role of energy, and 1/|w| plays the role of temperature. Small weights: a "hot", blurry transition with a wide band of uncertain points. Large weights: a "cold", sharp step. Watch the dashed lines (p = 0.1 and 0.9) move together as |w| grows.

The loss: log loss

For a blue point the model pays −log p; for a coral point −log(1 − p). A confident correct answer costs almost nothing, an unsure one costs about 0.69, and a confident wrong answer costs a lot. The gradient has a very simple form: for each point, (p − label) × input. It looks exactly like the one in linear regression, just with p in place of ŷ.

Why the weights can grow forever

If a straight line separates the classes perfectly, making the sigmoid sharper always lowers the loss a little: correct answers get even more confident. So |w| keeps growing, and the system "cools towards absolute zero". The model becomes overconfident, and gradient descent never stops. Press Separable, run it, and watch |w|.

L2 regularization adds (λ/2)·|w|² to the loss: a spring that pulls the weights back towards zero. The weights stop where the pull of the data and the pull of the spring balance, and the model keeps an honest band of uncertainty.

Try this

  • Separable data, L2 off: run, and read |w| after the run stops. Then set L2 to 0.01 and run again.
  • Overlap: the accuracy cannot reach 100%, but the probabilities still make sense.
