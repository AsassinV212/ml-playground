How a tree predicts

        

          A decision tree is a chain of yes/no questions about the features. Start at the top (the
          root), answer "is x < 1.3?", go left or right, answer the next question, and so on until
          you reach a leaf. The leaf holds the answer: the most common class of the training points that
          ended up there. On the plot every question is a straight cut parallel to an axis, so the plane is
          divided into rectangles.
        


        
How a tree is grown

        

          Finding the best possible tree is hopelessly slow, so it is grown greedily. At each node, try
          every feature and every threshold between neighbouring points, and pick the one that makes the two
          halves as pure as possible. Then repeat inside each half. Stop when the node is pure, the depth
          limit is reached, or a leaf would get too few points.
        


        
A physics picture: entropy

        

          Purity is measured with the same idea as entropy in statistical physics: how disordered the node is.
          For class shares p₁, p₂, …:
        

        
entropy = −Σ pᵢ · log₂ pᵢ        gini = 1 − Σ pᵢ²

        

          A node with only one class has zero entropy, like a perfect crystal. A 50/50 mix has one bit of entropy,
          like a gas in which every particle is equally likely to be anywhere. Each split is chosen to make the
          biggest drop in average entropy, the information gain. A good question is one whose answer
          tells you the most. Gini behaves almost the same and is a bit cheaper to compute.
        


        
Depth: from rough to memorizing

        

          A shallow tree draws a few big rectangles: simple, but it misses the shape (underfitting).
          A deep tree keeps cutting until every leaf is pure, and carves a tiny box around every noisy point
          (overfitting). Training accuracy reaches 100%, but those little boxes are wrong for new data.
          Max depth and min points per leaf are the brakes. See the overfitting
          page for how to choose them honestly.
        


        
Where greedy fails

        

          Press XOR and set depth to 1 or 2. In a perfect XOR pattern no single cut helps: both
          halves stay 50/50, so a greedy tree sees no reason to split at all, even though two cuts would solve
          the whole problem. Here a few noisy points let it start, but the first cut is often in a poor place.
          Looking only one step ahead is what makes trees fast, and also what makes them imperfect.
